# گزارش اعتبارسنجی نسخه 1.1.30

تاریخ ساخت نهایی: ۱۴۰۵/۰۷/۰۴ (2026-09-26)

## علت خطا و اصلاح اصلی

- گزارش Windows Error Reporting یک رخداد واقعی `AppHangB1` برای نسخه قدیمی
  برنامه نشان داد. مسیر قفل با ریست آداپتور گرافیکی هنگام نصب درایور هم‌زمان
  بود، نه با انتخاب پوشه یا اجرای عادی صف.
- رابط Flutter در سیستم‌های دارای دو GPU اکنون آداپتور کم‌مصرف/مجتمع را ترجیح
  می‌دهد تا نصب درایور NVIDIA یا AMD آداپتور مورد استفاده رابط را از دسترس خارج
  نکند. در سیستم تک‌گرافیکه Flutter به همان آداپتور موجود برمی‌گردد.
- نگهبان بومی Windows پس از `WM_DISPLAYCHANGE` یک فریم بازیابی درخواست می‌کند.
  اگر موتور رندر تا ۲۰ ثانیه فریم جدید ندهد، فقط رابط برنامه دوباره اجرا می‌شود؛
  Windows ری‌استارت نمی‌شود.
- بک‌اند برای ۳۰ ثانیه امکان تحویل نشست به رابط جایگزین را نگه می‌دارد. رابط
  جدید بک‌اند در حال اجرا را adopt می‌کند تا صف ترتیبی نصب درایورها از بین نرود.

## پایداری صف و وضعیت لحظه‌ای

- worker صف در یک مسیر قطعی `finally` وضعیت `is_running` را آزاد می‌کند؛ خطای
  غیرمنتظره دیگر دکمه‌های نصب را برای همیشه غیرفعال نگه نمی‌دارد.
- endpoint وضعیت، worker مرده را تشخیص می‌دهد، آیتم نیمه‌تمام را ناموفق علامت
  می‌زند و امکان «ادامه نصب» را برمی‌گرداند.
- گزارش اختصاصی درایورها در مسیر قابل‌نوشتن
  `%LOCALAPPDATA%\MarkaziSystemChecker\logs\driver_manager.log` ذخیره می‌شود.
- شمارنده نصب فقط افزایش واقعی آیتم‌های تکمیل‌شده را ثبت می‌کند و دیگر تعداد
  تجمعی را در هر poll دوباره جمع نمی‌زند.
- اسکن کامل WMI پس از تک‌تک درایورها حذف شد. وضعیت صف همچنان هر ۱٫۵ ثانیه
  تازه می‌شود، ولی اسکن سخت‌افزار و پوشه فقط یک‌بار پس از پایان صف انجام می‌شود؛
  برای صفی که درایور GPU داشته باشد ۸ ثانیه فرصت تثبیت نمایشگر در نظر گرفته شده
  است.
- خطای موقت دریافت status دیگر به اشتباه به معنی پایان صف تفسیر نمی‌شود.

## کنترل امن پنجره‌های نصاب درایور

- پنجرهٔ Welcome نصب‌کننده‌های InstallShield/Lenovo و دکمه‌های استاندارد
  `Next`، `Install`، `Finish`، `Close` و `OK` اکنون فقط در پنجره‌های متعلق به
  همان زنجیرهٔ پردازش نصب به‌صورت خودکار انجام می‌شوند.
- پیام‌های موفقیت مانند `Intel Serial-IO Driver installed successfully` بسته
  نمی‌مانند؛ پنجره قبل از ارسال `BM_CLICK` فعال می‌شود. این کار مطابق مستند
  رسمی Win32 است، چون کلیک روی دکمهٔ یک dialog غیرفعال ممکن است نادیده گرفته
  شود.
- child و grandchildهای نصاب با تاریخچهٔ parent PID دنبال می‌شوند. helper جدیدی
  که توسط OEM در همان پوشهٔ انتخاب‌شده اجرا شود نیز قابل شناسایی است، ولی عنوان
  عمومی `Setup` به‌تنهایی مجوز کنترل یک پنجرهٔ نامرتبط نیست.
- تمام پیام‌های کنترلی Win32 دارای timeout هستند؛ یک پنجرهٔ OEM هنگ‌کرده دیگر
  thread کنترل صف را برای همیشه قفل نمی‌کند.
- هر بار فقط یک اقدام انجام می‌شود و بین تغییر صفحه‌ها فاصلهٔ کوتاه وجود دارد؛
  بنابراین تیک توافق‌نامه دوباره برداشته نمی‌شود و چند مرحله با یک اسکن رد
  نمی‌شوند.
- `Restart later` انتخاب می‌شود و تیک `Restart now` در صورت امکان برداشته
  می‌شود. اگر تنها انتخاب موجود ری‌استارت فوری باشد، برنامه ادامه نمی‌دهد و آن
  گزینه را نمی‌زند.
- دکمه‌های maintenance و مخرب مانند `Uninstall`، `Remove`، `Repair`، `Modify`
  و `Cancel` هرگز به‌عنوان Install تشخیص داده نمی‌شوند.
- اگر child wizard هنوز باز باشد، صف به درایور بعدی نمی‌رود. پیاده‌سازی قدیمی و
  تکراری autopilot که پنجره‌ها را فقط از روی عنوان عمومی کنترل می‌کرد حذف شد.

## تست و اعتبارسنجی

- Backend unit tests: ۱۲۲ تست موفق.
- `flutter analyze`: بدون خطا یا هشدار.
- `flutter test`: ۳۶ تست موفق.
- تست‌های رگرسیون جدید، آزادشدن صف بعد از exception، ترمیم worker متوقف، مسیر
  قابل‌نوشتن لاگ، تحویل نشست بک‌اند، حفظ دسته `gpu` در مدل رابط، پنجره Welcome،
  پیام موفقیت/OK، توافق‌نامه، childهای کوتاه‌عمر، timeout پنجره و جلوگیری از
  Restart now/Uninstall را پوشش می‌دهند.
- Windows Release با Flutter 3.44.8 با موفقیت کامپایل شد؛ بنابراین کد C++
  مربوط به انتخاب GPU، پایش فریم و اجرای مجدد رابط نیز در پیکربندی Release
  تأیید شده است.
- بک‌اند بسته‌بندی‌شدهٔ نهایی روی پورت ایزوله 18102 اجرا شد؛ health نسخه `1.1.30`،
  قرارداد API نسخه 2، تحویل موفق نشست و صف غیرفعال/worker غیرفعال را برگرداند
  و سپس clean shutdown شد.
- سناریوی تحویل واقعی نیز روی پورت ایزوله 18101 شبیه‌سازی شد: process رابط
  اولیه پایان یافت، رابط جایگزین در بازهٔ grace نشست را تحویل گرفت و بک‌اند و
  وضعیت صف پس از hand-off در دسترس ماندند.
- هیچ برنامه یا درایور واقعی نصب نشد، هیچ تنظیم سیستمی تغییر نکرد و Windows
  ری‌استارت نشد.
