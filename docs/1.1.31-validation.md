# گزارش اعتبارسنجی نسخه 1.1.31

تاریخ ساخت نهایی: ۱۴۰۵/۰۷/۰۴ (2026-09-26)

## اصلاح سیاست Windows Home

- تشخیص Windows 10/11 Home اکنون پیش از ساخت صف نصب انجام می‌شود. در این
  نسخه‌ها هیچ مرحلهٔ `kms_activate` یا `office_extract` وارد صف نمی‌شود و بستهٔ
  نصب Microsoft Office نیز حتی در صورت انتخاب صریح کاربر اجرا نخواهد شد.
- محافظ Home فقط وابسته به UI نیست. نصب تعاملی Office، نصب خودکار Office،
  اجرای مستقیم ابزار فعال‌سازی، استخراج Office/KMS و اجرای `WINDOWS.cmd` همگی
  در خود بک‌اند دوباره سیاست Home را بررسی می‌کنند.
- اگر یک درخواست قدیمی یا دست‌ساز آیتم KMS را به worker صف برساند، آیتم بدون
  استخراج یا اجرای فایل به حالت `skipped` می‌رود.
- روی Home مرحلهٔ مستقل «ساخت میانبرهای Office» اجرا می‌شود. این مرحله فقط
  فایل‌های نصب‌شدهٔ `WINWORD.EXE`، `EXCEL.EXE` و `POWERPNT.EXE` را پیدا می‌کند
  و میانبرهای Word، Excel و PowerPoint را روی Desktop می‌سازد؛ هیچ نصب یا
  فعال‌سازی انجام نمی‌دهد.
- دکمهٔ ساخت میانبرهای Office در صفحهٔ نرم‌افزارها روی Home حتی وقتی وضعیت
  رجیستری بستهٔ نصب هنوز `نصب نشده` گزارش شده باشد در دسترس می‌ماند، در حالی
  که خود دکمهٔ نصب همچنان غیرفعال است.

## رفتار نسخه‌های غیر-Home

- نصب خودکار و دکمهٔ فعال‌سازی Windows از همان پوشهٔ نرم‌افزار انتخاب‌شده
  (برای مثال `H:\PROGRAM`) استفاده می‌کنند؛ وابستگی مسیر Windows activation به
  مقدار ثابت قدیمی `H:\KMS v6` حذف شد.
- آرشیوهای KMS در ریشهٔ PROGRAM بررسی می‌شوند و `KMS v6` نسبت به بسته‌های
  قدیمی‌تر اولویت قطعی دارد. آرشیو داخل همان PROGRAM استخراج می‌شود و
  `WINDOWS.cmd` همان درخت با ورودی منوی `1` اجرا می‌شود.
- اگر KMS v6 قبلاً استخراج شده باشد، استخراج تکراری انجام نمی‌شود. مسیر
  fallback بسته‌بندی‌شده نیز هنگام انتخاب PROGRAM استفاده نمی‌شود تا فایل
  اشتباه اجرا نشود.
- آیکن‌های This PC، Control Panel و Recycle Bin فقط پس از تأیید تجمیعی فعال
  بودن Windows اعمال می‌شوند.
- با اصلاح کلید تشخیص edition، Windows Update Blocker دیگر به‌صورت خودکار روی
  Home وارد صف نمی‌شود.

## تست‌های ایمنی و رگرسیون

- Backend unit tests: ۱۳۱ تست موفق.
- `flutter analyze`: بدون خطا یا هشدار.
- `flutter test`: ۳۷ تست موفق.
- تست‌های جدید با process runnerهای mock ثابت می‌کنند که در Home هیچ ابزار
  فعال‌سازی، نصاب Office، آرشیو KMS یا Office اجرا/استخراج نمی‌شود؛ درخواست
  صریح Office فقط به ساخت میانبر تبدیل می‌شود؛ و روی Pro آرشیو `KMS v6` پیش از
  اجرای دستور انتخاب می‌شود.
- هیچ فعال‌ساز، نصاب یا تنظیم سیستمی واقعی در تست‌ها اجرا نشد. درایو
  `H:\PROGRAM` هنگام اعتبارسنجی نهایی متصل نبود، بنابراین بررسی با fixture و
  mock انجام شد و هیچ داده‌ای روی فلش تغییر نکرد.
