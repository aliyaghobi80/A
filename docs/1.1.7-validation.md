# Markazi System Checker 1.1.7 — validation record

## Request and acceptance criteria

Compare the current implementation with 1.1.3 (`e09a5bf`); investigate fresh
Windows 10 startup without a vendor graphics driver. Preserve automatic software
installation, improve sequential driver coverage without forcing a reboot, use
GetX for asynchronous UI state, simplify the brand splash to a four-second
logo/word sequence, and produce Setup and portable ZIP artifacts.

## Implemented in this revision

- Parse all INF metadata and attempt all INF files in an INF-only package.
  Preserve individual failures and reboot-required status. Do not pass `/reboot`.
- Remove the depth-two discovery limit; avoid descending through links/junctions.
- Do not collapse separate component packages merely because their hardware ID
  prefix or display name matches.
- Fix the missing `Tuple` import and JSON conversion in the problem-device query.
- Guard concurrent driver/software queue starts and overlapping driver status polls.
  Ignore stale scan responses. Stop the remaining queue on installer timeout.
- Scope wizard interaction to the launched process ID, not generic window titles.
  Explicitly choose `Restart later` when that option is offered, never choose
  `Restart now`, and show a manual-restart reminder after the queue. Scripts
  containing an explicit restart command are blocked from automatic execution.
  Known silent installation
  commands remain enabled; this is not a promise of unattended support for every EXE.
- Replace the decorative hardware splash with a four-second logo/word animation,
  theme colors, reduced-motion support, and explicit startup failure/retry state.
  Remove the four unused legacy splash components.
- Add native first-frame diagnostics, repair 64-bit parent-watchdog handle types,
  and remove process-image-wide backend termination from the Windows runner.
- Stop transplanting build-host `ucrtbase.dll`/`d3dcompiler_47.dll` into the app
  root. PyInstaller's own Python runtime dependencies remain in `_internal`.
  Packaging now fails when a required file cannot be copied or archived.

## Evidence and limitations

The Windows runner source had no difference between `e09a5bf` and the previous
HEAD. The renderer/SDK, build dependencies, and Dart startup path still matter.
An actual fresh Windows 10 VM with Microsoft Basic Display Adapter has **not**
been tested here. This revision adds mitigation and diagnostic visibility, not a
verified universal graphics compatibility fix. Flutter's stock Windows release
wrapper has no supported DartProject switch for forcing software rendering;
passing Dart arguments would not implement such a fallback.

Driver unit tests simulate installation; they do not modify this machine's
drivers. Vendor setup launchers may require package-specific switches or manual
interaction. A root setup plus several nested independent driver installers is
still an ambiguous package boundary and needs representative media tests.
PnPUtil staging success alone does not prove a driver is bound to a device.

## Official driver-format references (reviewed 2026-09-10)

- [Microsoft PnPUtil syntax](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/pnputil-command-syntax):
  INF installation, subdirectories, optional reboot; Windows chooses compatible
  drivers by rank rather than forcibly replacing every device driver.
- [ASUS driver installation](https://rog.asus.com/support/faq/1045127/):
  downloaded driver packages and vendor setup workflow.
- [MSI driver installation troubleshooting](https://www.msi.com/support/technical_details/MB_Driver_Inst_Fail):
  use the correct motherboard/OS package and its installation instructions.
- [GIGABYTE driver archive index](https://download1.gigabyte.com/Files/Driver/):
  examples of ZIP-distributed motherboard packages.
- [ASRock support](https://www.asrock.com/support/index.asp?Model=driver):
  model-specific packages, including ZIP downloads.

Brand names do not define an EXE's command-line syntax. Archives must be extracted
with their supporting files intact. Never run every nested EXE indiscriminately:
driver packages can also contain uninstallers, firmware tools, and helper binaries.

## Required acceptance testing before customer deployment

1. Fresh Windows 10 x64, Basic Display Adapter, offline: confirm first frame and
   dashboard. On failure collect `%LOCALAPPDATA%/MarkaziSystemChecker/logs/startup.log`.
2. Test a representative motherboard package from ASUS, MSI, GIGABYTE and ASRock;
   compare selected package count and Device Manager before/after.
3. Exercise MSI, known EXE, an unknown/manual installer and VLC install detection.
4. Verify no automatic restart, preserve user files, and compare Setup/portable
   execution from a non-ASCII path on removable storage.
5. Only after these checks treat this as a validated customer release.

## Supplied-media dry run

- `H:/PROGRAM`: 10 executable entries found without launching any of them. The
  real Acrobat, FDM, Chrome MSI, KMPlayer, Office command, Firefox, VLC and WinRAR
  installers were accepted for automatic installation. Both Windows Update
  Blocker executables were correctly treated as portable/manual tools. Installed
  VLC was detected as version 3.0.21 through registry plus executable evidence.
- `H:/ROG STRIX B860-F GAMING WIFI`: 11 package groups found. The 8 actual `DRV_`
  groups contain 27 INF files in total; all are preserved for PnPUtil processing.
  The Armoury Crate uninstall tool was excluded. AI Advisor, Armoury Crate and
  Intel platform software remain non-recommended utilities rather than being
  silently treated as hardware drivers. The supplied `DRV_` files explicitly
  target Windows 11 and are skipped on Windows 10.
